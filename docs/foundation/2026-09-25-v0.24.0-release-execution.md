# v0.24.0 Native xAI Provider Release

## Objective

Publish VRO-18 as Agent Vesper v0.24.0 after live SuperGrok acceptance and
fresh exact-commit release gates. The release adds xAI as a native provider
without changing Alex's installed Agent Vesper.

## Release content

- Two explicit xAI authentication and billing modes: Grok account / SuperGrok
  session, and separately billed xAI API key.
- Native browser and device-code login, bounded refresh/logout, fixed trusted
  origins, Vesper-owned credentials and no Grok Build runtime dependency.
- Authenticated discovery intersected with an evidence-backed model capability
  index, including exact reasoning, modality, endpoint and tool constraints.
- Native Responses and first-party Grok session-proxy transports, streaming,
  shared Vesper function calls, structured output, image input, usage, typed
  errors, cancellation and opaque reasoning continuation.
- Explicit prompt-cache routing, provider-native compaction and WebSocket
  support where the selected API-key path supports them.
- Explicit opt-in provider-hosted tools and citations, kept distinct from
  Vesper tools and hidden for the Grok session path after a controlled live
  rejection.
- TUI and ACP composition through the shared provider registry, preserving
  provider-neutral voice, skills, memory, VRO, workers and permissions.

## Candidate and live evidence

The live-accepted implementation candidate is
`26ec33271badfc9e4fe00d2f3a2faa919d14f32c`. Its release tree, including the
v0.24.0 metadata and the platform repairs below, passed `cargo xtask verify`,
`cargo xtask msrv`, `cargo audit`, `cargo deny --all-features check`,
`cargo fmt --all -- --check`, `git diff --check` and Registry JSON/version
validation before the release commit was created. A temporary verification ref
ran five-target foundation workflow `36135566479` and web-driver workflow
`36135571078` before the version commit was integrated.
The first five-target run is retained as red evidence: Apple Silicon exposed
a fixed-sleep playback fixture race; Linux x86_64 exposed transient ETXTBSY
while launching a newly written TTS fixture; and Windows exposed a Unix-only
credential test backend plus an undersized one-second oversized-SSE observation
budget. The replacement commit carries deterministic repairs and must rerun the
whole matrix.

The first local canonical attempt ran concurrently with the complete MSRV suite
and five ACP transcript fixtures exceeded their one-second process-start
observation. The exact transcript suite then passed 7/7 in isolation, and the
full canonical command passed when rerun without competing workspace tests. No
product or timeout contract was changed for that local load artifact.

Real SuperGrok acceptance passed account discovery, text streaming, shared
`read_file` and `run_command` execution exactly once, multi-turn continuation,
cancellation and later recovery, image input, usage/status, logout, device
re-authentication and a fresh turn. The public API-key route is fixture-tested;
no live API-key request was made because a separately billed credential was not
provided. No authentication mode silently falls through to the other.

## Deviations and unresolved items

- Live public API-key acceptance was not run. VRO-18 §30.2 makes that route
  conditional on Alex choosing to provide separately billed API credits;
  implementation and loopback coverage pass.
- Grok-session hosted tools, native compaction and WebSocket are not advertised;
  current verified support for those features is restricted to the applicable
  Global/API-key path.
- Subscription allowance is unavailable through the verified first-party
  session protocol and is reported as unavailable rather than estimated.
- Exact-release workflows, publication, checksums and Registry synchronization
  remain open until their receipts replace the pending rows above.
- Initial candidate run `36135566479` failed and is not acceptance evidence.
  The playback test now observes the fixture process state instead of sleeping;
  the production subprocess route retries only `ExecutableFileBusy` twice and
  has a deterministic Linux red/green regression; xAI credential fixtures are
  cross-platform in-memory secrets behind the real lock path; and the oversized
  SSE test retains a bounded five-second Windows observation budget.
