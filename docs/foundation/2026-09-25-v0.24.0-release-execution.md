# v0.24.0 Native xAI Provider Release

## Objective

Publish VRO-18 as Agent Vesper v0.24.0 after live SuperGrok acceptance and
fresh exact-commit release gates. The release adds xAI as a native provider
without changing Alex's installed Agent Vesper.

## Release content

- Two explicit xAI authentication and billing modes: Grok account / SuperGrok
  session, and separately billed xAI API key.
- Native browser and device-code login, bounded refresh/logout, fixed trusted
  origins, Vesper-owned credentials and no Grok Build runtime dependency.
- Authenticated discovery intersected with an evidence-backed model capability
  index, including exact reasoning, modality, endpoint and tool constraints.
- Native Responses and first-party Grok session-proxy transports, streaming,
  shared Vesper function calls, structured output, image input, usage, typed
  errors, cancellation and opaque reasoning continuation.
- Explicit prompt-cache routing, provider-native compaction and WebSocket
  support where the selected API-key path supports them.
- Explicit opt-in provider-hosted tools and citations, kept distinct from
  Vesper tools and hidden for the Grok session path after a controlled live
  rejection.
- TUI and ACP composition through the shared provider registry, preserving
  provider-neutral voice, skills, memory, VRO, workers and permissions.

## Source and candidate history

The live-accepted implementation candidate was
`26ec33271badfc9e4fe00d2f3a2faa919d14f32c`. The final release commit is
`bd49ce69f4e34a64822245e67bdeee2503e1ce4d`. The annotated `v0.24.0` tag
dereferences to that exact commit.

The first temporary five-target run, `36135566479`, exposed three defects:

- Apple Silicon used a fixed-sleep playback fixture;
- Linux x86_64 could observe `ExecutableFileBusy` while launching a freshly
  written TTS fixture;
- Windows used a Unix-only credential test backend and an undersized
  oversized-SSE observation budget.

The fixes replaced the sleep with process-state observation, bounded the
production ETXTBSY retry to two 50 ms retries with a deterministic regression,
used a cross-platform in-memory test credential store, and retained a bounded
five-second oversized-SSE observation.

The first version candidate then failed only the macOS Intel command-settlement
case in five-target run `36139515810`. Leader reaping had a 500 ms deadline
followed by a separate two-second pipe deadline even though both operations ran
concurrently. The repair gives both operations one shared 2.5-second settlement
deadline, preserving the total cleanup bound. Twenty consecutive local
cancellation/cleanup runs and the complete nine-case settlement suite passed
before the final commit.

## Live SuperGrok evidence

Real SuperGrok acceptance passed browser and device authentication, account
model discovery, text streaming, shared `read_file` and `run_command` execution
exactly once, multi-turn continuation, bounded cancellation and later recovery,
image input, usage/status, logout, re-authentication and a fresh turn. The
public API-key route is fixture-tested; no live API-key request was made because
Alex did not provide a separately billed credential. No authentication mode
silently falls through to the other.

The session proxy rejected one controlled provider-hosted Web Search request.
Grok-session hosted tools, native compaction and WebSocket are therefore not
advertised. Those controls remain restricted to verified Global/API-key paths.
Subscription allowance is reported unavailable because the verified session
protocol provides no authoritative balance.

## Deviations and unresolved items

- Live public API-key acceptance was not run. VRO-18 §30.2 makes that route
  conditional on Alex choosing to provide separately billed API credits;
  implementation and loopback coverage pass.
- Grok-session hosted tools, native compaction and WebSocket remain explicitly
  unsupported/fail-closed pending first-party evidence and separate acceptance.
- Subscription allowance remains unavailable through the verified first-party
  session protocol and is not estimated.
- xAI Voice and Imagine remain separate future provider-neutral integrations.

These are scoped capability limitations, not open release blockers.
