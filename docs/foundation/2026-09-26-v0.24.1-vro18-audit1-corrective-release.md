# v0.24.1 VRO-18 Audit 1 Corrective Release

## Objective

Publish the exact accepted VRO-18 Audit 1 repairs as Agent Vesper v0.24.1
without waiting for Audit 2 or Audit 3 and without changing Alex's installed
application.

## Release content

- Prevent stale API-key-only attachment-search state from entering a
  Grok-session request. Settings projection and request dispatch both intersect
  capabilities with the selected authentication mode; incomplete attachment
  configuration fails safely without blocking ordinary turns.
- Launch and copy browser OAuth links from complete structured URL state, never
  reconstructed terminal lines. Narrow-terminal wrapping affects presentation
  only; the client ID, redirect URI, scopes, PKCE challenge/method, state and
  nonce remain complete.
- Provide automatic browser launch, exact-link copy and visible device-code
  fallback when launch fails.
- Preserve native browser/device authentication, Vesper-owned refreshable
  credentials, logout/reauthentication, SuperGrok/API-key billing isolation, no
  API-key fallback and no Grok Build runtime dependency.

## Methods and commands

The release process uses a disposable target on the main filesystem, never the
quota-limited `/tmp` target. Local and remote commands include:

```text
cargo xtask verify
cargo +1.88.0 xtask msrv
cargo clippy --workspace --all-targets --all-features -- -D warnings
cargo fmt --all -- --check
cargo xtask architecture
cargo xtask naming-guard
cargo xtask acceptance
cargo deny --all-features check
cargo audit
jq . registry/agent.json
```

The final version commit is pushed to `main`, and successful push runs for
canonical CI, MSRV, five-target foundation and web-driver/native-host are
required on that exact SHA before an annotated `v0.24.1` tag is created.

The first exact-commit web-driver run found that Debian had retired the pinned
Chromium 153 package from both current Bookworm Security indexes. The release
candidate was repaired by advancing the existing immutable
`chromium-headless-shell` pin to `154.0.8037.57-1~deb12u1`, the version present
for both `amd64` and `arm64`; no browser acceptance step was weakened or
removed.

The next five-target run caught a Windows-only defect in the new xAI ACP
exactly-once acceptance: its marker command used Unix `printf`. The test now
uses the platform's native command shell on Windows while preserving the same
append-based one-execution assertion; production behavior was unchanged.
The first native Windows forms proved unreliable through `cmd /C`, so the final
test uses the shell's built-in `echo` append and asserts one logical marker line
independent of CRLF encoding. The final form uses a fixed relative marker in
the isolated workspace, avoiding platform-specific absolute-path quoting while
also proving the tool's selected working directory. The same run
also exposed an unrelated timer race in the Unix partial-output cancellation
test on Apple Silicon; cancellation now waits for a command-created readiness
barrier before asserting that visible partial output was preserved.
