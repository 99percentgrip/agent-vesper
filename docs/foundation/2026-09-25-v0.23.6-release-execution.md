# v0.23.6 Critical Executor-Stability Release

## Objective

Publish the accepted classification-D shared command-executor repair as Agent
Vesper v0.23.6 without changing Alex's local installation. The release retains
the exact settlement behavior verified at candidate
`27a3f17bd818294e1a52e0bf194b02ba761e3464` and requires fresh exact-release-
commit canonical, MSRV, five-target foundation and web-driver evidence before
the immutable tag is created.

## Release Content

- Drain stdout and stderr concurrently throughout command execution.
- Bound retained model-visible output independently from transport draining.
- Bound timeout, explicit cancellation and caller-abort settlement.
- Own and clean up command descendants with POSIX process groups and Windows
  Job Objects, including descendant-held output pipes.
- Return truthful partial output, truncation, exit, timeout, cancellation and
  cleanup state without replaying an ambiguous command.
- Keep the production-boundary nine-case settlement matrix enabled on every
  supported native CI runner.

The historical observation that stalls appeared more frequently with OpenAI
was not live-retested because GLM live access is unavailable. No frequency
explanation is inferred. This is an explanatory limitation, not a release
blocker for the provider-neutral executor defect reproduced red and repaired
green.

## Deviations and Unresolved Items

- Matched live OpenAI-versus-GLM provider correlation: **NOT EXECUTED — GLM
  live access unavailable**. Fixture-backed adapter parity and the direct
  provider-neutral executor reproduction remain the applicable evidence.
- Historical incident executable identity is not byte-proven. Current source
  independently reproduced the defect at the real `RunCommand` boundary, so
  that provenance limitation does not block this release.
- The first local canonical attempt exhausted the isolated `/tmp` build
  filesystem while writing test artifacts. Generated targets in temporary
  worktrees were removed, the build target was moved to the persistent cache,
  and the complete command then passed. No source failure was hidden.
- The first exact-release five-target run exposed a pre-existing race in the
  device-free voice pipeline fixture on macOS Apple Silicon: the fixture left
  its successful-completion marker active while asserting that Stop must win
  after first PCM. The CI failure returned `Spoke` instead of `Stale`. The
  fixture now removes that marker before the Stop case and restores it before
  the recovery case, making the intended ordering deterministic without a
  production voice change. The failed run was `36063913379`; the corrected
  test passed five consecutive targeted runs, its complete two-case suite and
  strict TUI Clippy locally, then all five native jobs in `36065369608`.
